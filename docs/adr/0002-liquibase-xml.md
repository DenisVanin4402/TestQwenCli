# ADR-002. Liquibase XML и единая история схемы

**Статус:** Принят. **Редакция:** 04.10.2026.

## Причина

Прикладные таблицы и native-хранилище FSM должны создаваться воспроизводимо одним механизмом, без конкурирующей генерации схемы.

## Решение

- Единственный master changelog располагается в `agent-db/src/main/resources/db/changelog/`; changeset-файлы — в общем плоском каталоге `changeset/`, с последовательной нумерацией и явным порядком подключения.
- Формат changelog — XML. SQL внутри changeset допустим для нужной особенности БД. Второй master, Flyway, ручное создание таблиц при старте и Hibernate `create/update` не используются; Hibernate проверяет схему через `validate`.
- Таблицы штатного JPA persister SSM включаются в ту же историю миграций. Внешняя библиотека не управляет ими параллельно с Liquibase.
- Целевая схема упрощённого POC содержит постоянный семафор сессии, необходимое formatId и native-состояние FSM. Не вводятся таблицы binding, командного журнала, владельцев исполнения, попыток corr или аудита. Ответственность данных — [ADR-006](0006-model-entities-dto-enums.md), [ADR-008](0008-replaceable-fsm.md), [ADR-010](0010-session-execution.md).
- Старых бизнес-данных нет: перенос checkpoint, конвертеры форматов и двойное чтение не нужны. Это не разрешение очищать БД или переписывать применённые changeset. Изменение ранее развёрнутой схемы оформляется следующей миграцией; историю применённых миграций сохраняем.
- PostgreSQL и H2 используют общий master. Различия типов и SQL выражаются средствами Liquibase с явной принадлежностью БД; отдельная несогласованная схема для тестов не создаётся.

## Проверка

Миграции и JPA validate проверяются на чистой PostgreSQL и локальной H2 по [ADR-003](0003-h2-persistence-and-runtime.md) и [ADR-017](0017-spring-http-and-database-acceptance.md). При наличии уже применённой схемы проверяется её обновление. Копировать отчёты Maven в документацию не требуется.
