# ADR-003. PostgreSQL, локальная H2 и профили запуска

**Статус:** Принят. **Редакция:** 04.10.2026.

## Причина

Быстрый локальный запуск полезен, но не доказывает работу блокировок и native persistence на целевой БД.

## Решение

- Целевая БД — PostgreSQL. H2 допустима для локальных DB-тестов и демонстрации с настоящими Liquibase, JPA, транзакциями и persister FSM.
- Рабочий профиль явно выбирает `h2` либо `postgres`. Профиль `bootstrap` проверяет сборку приложения без рабочего persistence и не совмещается с ними. Ошибка подключения PostgreSQL не переключает приложение на H2 или память.
- Схема создаётся Liquibase по [ADR-002](0002-liquibase-xml.md), Hibernate использует `validate`. Профили БД не выбирают автоматически stub/real corr.
- Семафор и native-состояние FSM находятся в одной БД и участвуют в одной рабочей JPA-транзакции. Отдельная короткая транзакция создания семафора описана в [ADR-010](0010-session-execution.md).
- PostgreSQL отдельно проверяется на миграциях, сериализованном native-состоянии/LOB, rollback и конкуренции. H2 не подтверждает выполнение NOWAIT на PostgreSQL; различия провайдера и диалекта учитываются по фактическому SQL.

## Проверка

Достаточны проверки действующего сценария и конкретных различий БД по [ADR-017](0017-spring-http-and-database-acceptance.md). Запуск без реального persistence не выдаётся за проверку сохранения FSM. Дополнительные in-memory хранилища для обхода обязательных DB-проверок не создаются.
