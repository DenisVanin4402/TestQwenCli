# ADR-010. Семафор сессии и последовательное исполнение

**Статус:** Принят. **Редакция:** 06.10.2026. Выбранная [task06, A](../tasks/task06/arch_design.md) добавляет внутреннее чтение для навигации после справки/уточнения и по «Да». [Дизайн реализации](../tasks/task06/impl_design.md) и [задачи](../tasks/task06/tasks.md) явно согласованы 07.10.2026; код реализован, автоматические проверки пройдены; браузерная приёмка открыта.

## Причина

Одна рабочая транзакция уже сериализует действия с одной FSM. Дополнительный протокол владельца, токенов и восстановления исполнителя для этого не нужен.

## Решение

Постоянная техническая запись с уникальным sessionId — семафор единоличной работы с машиной. Для этой ответственности используется SessionEntity/agent_session; вторая дублирующая таблица не создаётся. Наличие строки означает регистрацию сессии, но **не существование native FSM и не занятость**.

1. Перед рабочей транзакцией обеспечить строку отдельной короткой транзакцией/autocommit. Для PostgreSQL подходит INSERT ON CONFLICT DO NOTHING. Уникальный ключ относится ко всей сессии, не к requestId или операции. После commit строка остаётся независимо от дальнейшего результата.
2. Начать рабочую JPA-транзакцию и взять строку SELECT FOR UPDATE NOWAIT. Только эта блокировка даёт право читать и изменять FSM. При занятой строке вернуть SESSION_BUSY без очереди, Action и повторного захвата.
3. После захвата проверить сохранённое состояние. Если native FSM отсутствует, создать её только для допустимой первой команды и полного начального контекста. Если существует — проверить formatId и восстановить. Ошибка чтения/десериализации не означает отсутствие.
4. Исполнить событие и сохранить машину с прикладными данными по ADR-009. Commit/rollback освобождает блокировку; строка семафора не удаляется.

Если первая инициализация откатилась, семафор остаётся, а FSM нет. Следующий допустимый вход захватывает ту же строку, создаёт FSM и выполняет событие. Это новый входящий запрос, не автоматический retry операции. Неполный последующий запрос нельзя использовать для выдумывания недостающего исходного контекста.

Все пути изменения одной FSM используют этот семафор **до чтения состояния**. Проверки expectedRevision, появившиеся только из-за старого раздельного load/apply, удаляются. Сохраняются проверки принадлежности данных и согласия на конкретную подготовку: блокировка не заменяет бизнес-правила.

NOWAIT относится к захвату строки; конкурентная первая вставка может кратко ждать уникальный индекс. Нельзя обещать отсутствие любого ожидания SQL. Независимые сессии не блокируются общей строкой узла.

## Чтение и восстановление

Внутреннее чтение получает согласованный снимок под FOR SHARE NOWAIT в короткой транзакции, восстанавливает существующую машину без событий, сохранения или вызова corr. Отсутствие семафора/native FSM означает отсутствие сохранённой сессии; чтение их не создаёт. При конфликте с рабочим писателем возвращается занятость. Представление готовится после чтения вне FSM по ADR-004. Публичный GET сессии удалён по ADR-020.

По выбранному A [task06](../tasks/task06/arch_design.md) LLM остаётся вне транзакции. После справки/уточнения сервер получает текущий снимок для выбора кнопок; если снимок уже вернул текущий бизнес-ход, повторно его не читает. При предметном отказе без снимка чтение выполняется после завершения транзакции отказа. На старте/без FSM предлагаются операции, на активном шаге — «Да»/«Нет», на завершении — никаких действий. Чтение не создаёт семафор/native FSM и не пишет данные. Ошибка чтения не означает отсутствие операции. Прежний запрет чтения task04/05 заменён только в этой области.

«Да» повторно читает актуальный снимок и показывает шаг без событий/записи. «Нет» получает исключительную блокировку существующей сессии до восстановления и отменяет подготовку через SSM в одной транзакции; предварительный find и последующая отдельная отмена не допускаются. При отсутствии FSM начальное меню не требует её создания. Терминальная сессия не сбрасывается. Исходный контекст и монотонный номер подготовок сохраняются.

Справка/уточнение не сравнивают projectionVersion, не повторяют LLM из-за смены шага и не меняют FSM. Чтения до LLM ради серверного запрета справки после завершения нет; запрет ввода остаётся клиентским. Завершённость, обнаруженная при оформлении ответа, отражается в ответе. Транзакционные гарантии банковских команд сохраняются.

БД освобождает транзакционные блокировки при завершении/обрыве соединения. Не нужны ExecutorNode, owner, bootGeneration, executionToken, fencing, ручное освобождение владельца или startup recovery этих записей. Сбой уже выполненного corr не решается семафором: ограничения временной реализации приведены в ADR-009/013.

## Проверка

На PostgreSQL проверить конфликт одной сессии, независимость разных сессий, сохранность семафора после rollback первой инициализации и создание FSM следующим допустимым входом. Проверить восстановление существующей FSM и согласованное чтение. Реальный SQL блокировки проверяется по [ADR-016](0016-spring-data-jpa-repositories.md), а не предполагается по одному имени JPA-аннотации.
