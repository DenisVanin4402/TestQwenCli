# ADR-011. Понятная документация кода на русском языке

**Статус:** Принят. **Редакция:** 05.10.2026. Сохраняет прямые требования пользователя ко всем этапам и существующему коду.

## Решение

Документация должна быть понятна человеку, впервые открывшему класс, без предварительного знания архитектуры. Русский текст объясняет предметный смысл и фактические гарантии, а не повторяет имена или строки реализации.

| Объект | Что документировать |
|---|---|
| Классы, интерфейсы, enum, вложенные и вспомогательные типы | Назначение, место в сценарии, ответственность и существенные ограничения. Javadoc, для JavaScript — JSDoc. |
| Каждое поле DTO, entity и value object | Предметный смысл; для неочевидного значения — источник, потребитель, идентичность, условия изменения. |
| Каждая константа enum | Значение, условия применения и отличие от близких вариантов. |
| Методы, включая приватные и вспомогательные | Контракт/преобразование/проверяемый инвариант и существенные эффекты; неочевидные параметры и результат. |
| Тестовый класс | Какое поведение или контракт проверяется. |
| Каждый тестовый метод или сценарий | Условие и наблюдаемый результат: Javadoc либо содержательный русский DisplayName/описание сценария. |

Правило охватывает DTO, конфигурации, исключения, адаптеры, заглушки и тестовые helpers. Для параметризованных тестов объясняются общее правило и различия случаев; для динамических — каждый сценарий. Английское имя теста не заменяет русского описания.

Обычно достаточно одного–трёх предложений; понятность важнее предельной краткости. Формулировки «сервис данных», «версия FSM», «корреляция» без объяснения назначения недостаточны. Например, operationId — идентификатор одной подтверждённой внешней операции, а не номер попытки вызова. Не заявлять гарантию дедупликации у маркерной аннотации или отмену corr при rollback БД.

В методах длиннее десяти строк и алгоритмах желательны внутренние комментарии о смысловых шагах, неочевидных проверках и важном порядке действий. Это ориентир читаемости, не требование комментировать каждую десятую строку. Javadoc не дублируется дословно в DisplayName и не заменяется пересказом кода.

## Генерация и проверка

Русские описания generated API/моделей/полей/enum задаются стандартными summary/description в OpenAPI. Используется штатное оформление OpenAPI Generator; собственные Mustache-шаблоны ради расположения комментариев или перевода технических методов не поддерживаются. Это уточнение принято пользователем 05.10.2026. Файлы target вручную не исправляются. Код сторонних библиотек не переписывается.

При изменении поведения документация актуализируется в том же изменении. Приёмка проверяет все типы и тесты соответствующего результата, включая ранее созданные. Review оценивает понятность и соответствие фактическому коду; новый инструмент, ArchUnit или тесты количества комментариев не нужны. Принятый ADR не означает, что весь существующий код уже приведён в соответствие.
