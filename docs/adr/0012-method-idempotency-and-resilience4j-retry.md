# ADR-012. Идемпотентность на входной границе

**Статус:** Принят. **Редакция:** 04.10.2026. Исходящие операции регулирует [ADR-013](0013-outbound-retry-and-timeouts.md); имя файла сохранено для существующих ссылок.

## Решение

Идемпотентность относится к входной обработке use case. Входной адаптер передаёт явный строковый ключ `sessionId:requestId` отдельным аргументом. Временная аннотация `@Idempotent` сохраняет атрибуты signature, needCheckHash, keyParameterIndex; индекс указывает на сам аргумент-ключ, не на DTO с идентификаторами.

Пользовательская библиотека ещё не подключена. **Текущая аннотация — маркер без AOP/runtime дедупликации.** Собственные InputRequest/replay/hash-хранилища удалены по указанию пользователя и не создаются повторно. Нельзя выдавать сохранённый повтор, конфликт payload или «ровно один внешний вызов при повторной доставке» за действующие гарантии.

Внутренние initialize/apply не аннотируются. Удаляются их ключи, commandId.toString(), журнал FSM-команд, replay/DUPLICATE и commandId без оставшихся потребителей. Не вводится другая внутренняя дедупликация взамен удалённой.

Семафор сериализует конкурентные действия, а guards проверяют состояние и согласие. Они не воспроизводят исходный HTTP-ответ на повтор и не заменяют входную библиотеку. operationId сохраняется как идентичность внешней операции по ADR-006/013; он не является ключом внутреннего вызова машины.

## Подключение библиотеки

После получения библиотеки проверяются её фактические правила ключа, конфликта содержимого, конкурентного входа, сохранения ответа и ошибки/rollback. Неуспешная инициализация не должна считаться успешно выполненным входом. Требования уточняются по реальному контракту библиотеки, без заранее созданного второго механизма.

Временно закомментированные по указанию пользователя тесты replay/конфликта Request-Id не считаются прошедшими. Они включаются/адаптируются при подключении библиотеки. Это явное ограничение POC, а не повод возвращать журнал команд, outbox или повтор WorkflowManager в агент.
