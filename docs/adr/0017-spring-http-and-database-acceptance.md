# ADR-017. Минимальная приёмка реального поведения

**Статус:** Принят. **Редакция:** 05.10.2026.

## Решение

Изменения поведения разрабатываются через TDD; обычный bug fix подтверждается регрессионным тестом. Документация, удаление ненужных тестов и кода без нового поведения не требуют искусственного RED.

Приёмка нового POC включает минимально достаточные проверки:

| Граница | Наблюдаемое поведение |
|---|---|
| Сценарий | Подготовка → отдельное согласие → один вызов WorkflowManager → COMPLETED; отказ, новый выбор после отказа и запрет отправки без согласия. В AWAITING_CONFIRM повторный status возвращает недопустимую команду без изменения подготовки и вызова corr; удалённый restart_status отклоняется до FSM. SSM сама выбирает переход. |
| Транзакция | Action выполняется в рабочей JPA-транзакции; ошибки Action/persistence откатывают прикладные данные и native FSM. Отдельный HTTP-тест с отложенным ограничением PostgreSQL проверяет отказ commit после успешного persist: failure вместо успеха, прежнее сохранённое состояние, отсутствие повторного corr. Ошибка, захваченная SSM, не превращается в успешный commit. |
| Семафор | Одна сессия не исполняет два Action одновременно; разные сессии не мешают друг другу. После сбоя первой инициализации семафор остаётся, следующий допустимый вход создаёт FSM. |
| Native persistence | Один экземпляр restore/execute/save, данные ExtendedState восстанавливаются, несовместимый formatId/повреждённый снимок не пересоздаётся как новая сессия. Внутреннее чтение не выполняет событие и corr; HTTP GET сессии отсутствует. |
| Corr | Корректный STATUS mapping и один Feign-вызов, без повторов при сбое; ошибка проходит к rollback. Внешний эффект не объявляется откатываемым. |
| HTTP | Настоящий Spring-контекст, ACL HTTP, Liquibase, JPA и SSM в одном связанном сценарии. Итоговые inform, status_code=200 и final_message=true только после успешного commit. |
| Упаковка | Короткий запуск собранного JAR в отдельной JVM с HTTP и реальной БД: профили, миграции и готовность приложения. |

Для HTTP подходит SpringBootTest(RANDOM_PORT); mock контроллера или отдельный вызов Java-метода его не заменяет. Corr можно заменить управляемой заглушкой. H2 проверяет локальную сборку; **PostgreSQL отдельно** подтверждает миграции, native LOB, rollback и реальное поведение NOWAIT.

Тесты подбираются по наблюдаемым гарантиям, не по одному тесту на каждую строку матрицы или методу. Общие фикстуры/наборы не дублируются. ArchUnit и искусственные Good/Bad fixtures исключены. После успешной необходимой проверки её не повторяют без нового изменения или нерешённой проблемы.

## Ограничения и отчёт

Реальная банковская интеграция, регистрация GA и доставка на его поверхности проверяются на соответствующем этапе; локальный ACL/stub этого не доказывает. Replay/конфликт входного payload временно не гарантированы по [ADR-012](0012-method-idempotency-and-resilience4j-retry.md); закомментированные проверки не считаются успешными.

Не сохраняются тесты удалённых журнала FSM, owner/fencing, applyResult и retry corr как требования к новой архитектуре. Не требуется доказывать распределённую атомарность, которую временный менеджер не предоставляет.

Фактические результаты проверки кратко фиксируются в истории этапа; стандартные отчёты остаются в target. Принятый ADR или наличие класса теста не означает успешной приёмки. Ради изменения документации Maven не запускается.
