# ADR-019. Отдельный модуль UI и локальное зеркало ACL

**Статус:** Принят. **Дата:** 05.10.2026. Основание — поручение пользователя о втором этапе.

## Решение

HTML/CSS/JavaScript и клиентские тесты находятся в отдельном Maven-модуле `agent-ui`. Он содержит ресурсы без frontend-фреймворка, npm-зависимостей и отдельного сервера. `agent-main` упаковывает его в исполняемый JAR; `agent-ui-back` публикует `/test-ui/` только в профиле `poc-local`.

Браузер вызывает `POST /local-api/api/v1/ai/agents/{agent_code}` — контроллер `LocalAclController` в `agent-ui-back`. Основной `POST /api/v1/ai/agents/{agent_code}` браузером не используется. Зеркало реализует тот же generated `AclApi` с префиксом `/local-api` и передаёт запрос существующему `AclInputAdapter`. HTTP-проксирования и копии валидации, mapping или бизнес-логики нет.

Для этого `agent-ui-back` зависит от `agent-api-in`: переиспользуются generated-контракт и адаптер. Это узкая зависимость локального тестового канала, предпочтительная копированию ACL или выделению нового общего модуля ради одного контроллера. Обратной зависимости нет. Оба контроллера доходят до одного `SessionTurnUseCase`.

По [ADR-020](0020-acl-chat-actions.md) единственный helper — GET fixtures с начальными suggestions. Все следующие действия и запросы согласия передаются в ACL-ответах. GET сессии, availableCommands и восстановление через sessionStorage удалены. Автоматического повтора POST нет.

## Область замены

Заменяет ограничение «только GET, без второго POST» для `agent-ui-back` в [ADR-005](0005-module-hierarchy.md) и прямой вход UI через основной ACL в [ADR-018](0018-first-stage-acl-profile.md). Формат ACL, общий use case, FSM и транзакции не меняются. Самостоятельный формат `{command, fixtureId}` не возвращается.

## Проверка

HTTP-тест зеркала, ресурсов и общей сессии; клиентские тесты двойного клика, корреляции, смены обращения, ошибок и отсутствия дополнительных GET; браузерный проход статуса и отказа. Проверка приложения — штатный Maven `verify`.
