## Область и источники решений

Уточнение task06 от 06.10.2026: пользователь требует три категории состояний — инициирующее, промежуточные, терминальное. Общая навигация зависит от категории; продолжение показывает конкретный шаг, включая будущую подготовку/ввод реквизитов, а отмена остаётся переходом SSM. Обновлены ADR-008/020 и согласованный дизайн task06; добавление самих будущих бизнес-шагов в эту задачу не входит.

06.10.2026 пользователь явно выбрал [A task06](../tasks/task06/arch_design.md). Готовый ответ в FSM не хранится: по «Да» представляется текущий шаг без действия; по «Нет» очищается подготовка с сохранением исходного контекста и номера. Прежние правила task04/05 «не читать FSM для справки/уточнения» и «сохранять старые кнопки при information» заменены в этой области. Точные DTO/локальное расширение ACL и список работ согласованы 07.10.2026 в [impl_design.md](../tasks/task06/impl_design.md)/[tasks.md](../tasks/task06/tasks.md); код реализован, автоматические проверки пройдены; браузерная приёмка открыта. Историческое основание переработки — архивное [критическое review](../stages/01_poc/old/architecture_simplicity_review.md) и [хронология ответов пользователя](../stages/01_poc/old/architecture_simplification_decisions.md), особенно §12–21. Поздние принятые ответы заменили ранние предложения; последовательность обсуждения сохранена там и в истории Git. План и спецификация возвращены в папку этапа и актуализированы. В ADR больше не требуется собирать правило из хронологических вставок.

Для POC действует один путь: входной адаптер → общий оркестратор → семафор и рабочая транзакция → SSM guards/synchronous transition actions → native save/commit → шаблон в оркестраторе → wire-ответ адаптера. Временный WorkflowManager вызывается из Action до commit, делает один STATUS-вызов corr, не возвращает бизнес-результат. Ошибка Action откатывает локальную транзакцию; внешний эффект необратим.

Удаляются журнал внутренних команд, лишние binding-версии, owner/fencing, раздельный corr-протокол и повторы агента. История действий, полноценный Outbox/УСС, реализация RECALL/DETAILS и старые данные для миграции не входят в текущий рефакторинг. Входной маркер не обеспечивает дедупликацию до подключения библиотеки.

На последующих этапах бизнес-операции, LLM/RAG и настоящий GA расширяют этот путь, а не возвращают снятые механизмы. Политика технических попыток LLM сохраняется отдельно. Внешние контракты и внутренний протокол полноценного менеджера остаются своими отложенными задачами.

[Документы этапов](../stages/README.md) используют эту редакцию. Исходные AC/таблицы старого протокола сохраняются только как трассировка и не являются разрешением снова реализовать журнал, retry corr, внешнюю transition policy или ответы в Action. Применимость заменённых пунктов явно указана в документах этапов.

## Обновление ADR

- Статусы: «Предложен», «Принят», «Заменён», «Отменён». Принятие фиксируется по решению пользователя; готовность кода указывается отдельно.
- При добавлении решения создать следующий номер и строку индекса. При замене указать область замены и ссылки в обоих документах; частичная замена не отменяет оставшуюся часть.
- Текущая консолидация выполнена в существующих файлах с сохранением номеров/URL: область замены названа в ADR, прежние редакции доступны в Git. Исторические основания не повторяются как параллельные нормы.
- Обновлять индекс, затронутые требования и планы вместе с ADR. AGENTS.md описывает процесс и не дублирует перечень решений.
- Противоречие не разрешается только большим номером ADR. При новой неопределённости сначала учитывать явные решения пользователя и фактический контракт, затем уточнять только оставшийся вопрос.
