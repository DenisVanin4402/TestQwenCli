## Область и источники решений

06.10.2026 выбран вариант A [task05](../tasks/task05/arch_design.md): RAG поверх STATUS, знания на 2–3 страницы целиком во втором промпте, LLM вне транзакции; составное сообщение разделять, для справки одна попытка. По уточнению пользователя на confirmation свободный ввод запрещён. Подготовлены глоссарий, бизнес-примеры и проекты знаний/промптов; до перехода к impl_design.md и tasks.md пользователь запросил обсуждение деталей. Архитектурный выбор не является разрешением на код.

05.10.2026 выбран вариант A [task04](../tasks/task04/arch_design.md): текстовый выбор STATUS через строгий JSON, до семафора и транзакции. При отсутствии команды — шаблонное уточнение без вызова FSM. Промпты — в YAML; отдельный прогон до 10 сообщений считает TP/TN/FP/FN и ошибки. Уточнены ADR-007/020; дизайн реализации и задачи явно согласованы, реализация проходит проверку.

05.10.2026 выбран вариант A [task03](../tasks/task03/arch_design.md): реальный клиент GigaChat перенесён в текущий этап; текстовый разбор на тот момент был оставлен MVP и затем уточнён task04. Уточнены ADR-001/007; дизайн реализации и задачи явно согласованы 05.10.2026; реализация и независимая [валидация task03](../tasks/task03/validation.md) завершены.

05.10.2026 пользователь выбрал [ADR-021](0021-direct-spring-statemachine.md): удалить абстракцию над SSM. Он частично заменяет требование ADR-005/008 о заменяемом движке. [Task02](../tasks/task02/arch_design.md) сохраняет поведение task01; дизайн реализации и задачи task02 согласованы 05.10.2026 с сохранением отдельных guards/actions; реализация проходит проверку.

05.10.2026 принята архитектура [task01](../tasks/task01/arch_design.md), уточняющая ADR-005/008/020. [Дизайн реализации](../tasks/task01/impl_design.md) и [задачи](../tasks/task01/tasks.md) согласованы; поведенческие требования проверяются при завершении task02. Ранее приведённые результаты тестов не являются проверкой task01.

Историческое основание переработки — архивное [критическое review](../stages/01_poc/old/architecture_simplicity_review.md) и [хронология ответов пользователя](../stages/01_poc/old/architecture_simplification_decisions.md), особенно §12–21. Поздние принятые ответы заменили ранние предложения; последовательность обсуждения сохранена там и в истории Git. План и спецификация возвращены в папку этапа и актуализированы. В ADR больше не требуется собирать правило из хронологических вставок.

Для POC действует один путь: входной адаптер → общий оркестратор → семафор и рабочая транзакция → SSM guards/synchronous transition actions → native save/commit → шаблон в оркестраторе → wire-ответ адаптера. Временный WorkflowManager вызывается из Action до commit, делает один STATUS-вызов corr, не возвращает бизнес-результат. Ошибка Action откатывает локальную транзакцию; внешний эффект необратим.

Удаляются журнал внутренних команд, лишние binding-версии, owner/fencing, раздельный corr-протокол и повторы агента. История действий, полноценный Outbox/УСС, реализация RECALL/DETAILS и старые данные для миграции не входят в текущий рефакторинг. Входной маркер не обеспечивает дедупликацию до подключения библиотеки.

На последующих этапах бизнес-операции, LLM/RAG и настоящий GA расширяют этот путь, а не возвращают снятые механизмы. Политика технических попыток LLM сохраняется отдельно. Внешние контракты и внутренний протокол полноценного менеджера остаются своими отложенными задачами.

[Документы этапов](../stages/README.md) используют эту редакцию. Исходные AC/таблицы старого протокола сохраняются только как трассировка и не являются разрешением снова реализовать журнал, retry corr, внешнюю transition policy или ответы в Action. Применимость заменённых пунктов явно указана в документах этапов.

## Обновление ADR

- Статусы: «Предложен», «Принят», «Заменён», «Отменён». Принятие фиксируется по решению пользователя; готовность кода указывается отдельно.
- При добавлении решения создать следующий номер и строку индекса. При замене указать область замены и ссылки в обоих документах; частичная замена не отменяет оставшуюся часть.
- Текущая консолидация выполнена в существующих файлах с сохранением номеров/URL: область замены названа в ADR, прежние редакции доступны в Git. Исторические основания не повторяются как параллельные нормы.
- Обновлять индекс, затронутые требования и планы вместе с ADR. AGENTS.md описывает процесс и не дублирует перечень решений.
- Противоречие не разрешается только большим номером ADR. При новой неопределённости сначала учитывать явные решения пользователя и фактический контракт, затем уточнять только оставшийся вопрос.
