# ADR-001. Исходящие клиенты: обязательный stub и Feign

**Дата:** 28.09.2026. **Статус:** принято по указанию заказчика. **Реализация:** запланирована, ещё не выполнена.

Связанные документы: [WBS и порядок приёмки](../plan/plans.md), [архитектура](../final/architecture.md), [интеграции](../final/integrations.md), [модули](../final/modules.md).

## Решение

У каждого прикладного исходящего клиента в `agent-api-out` обязательны две реализации одного контракта: **stub и реальный клиент**. Правило действует для Invest corr, GigaChat и последующих исходящих интеграций. Создание реального клиента без stub не считается завершённым шагом разработки. Речь о клиентах приложения, а не о реализации всех внутренних интерфейсов сторонней библиотеки.

Переключение задаётся только конфигурацией `application.yaml`:

```text
integrations.<integration>.stub = enabled | disabled
integrations.<integration>.url = базовый URL внешнего сервиса
```

`integrations` — корневой раздел, без префикса `agent`. Прежние `agent.integrations.*.mode` и `agent.llm.mode` больше не задают выбор реализации. Пользовательский JSON и LLM не могут менять режим интеграции.

Все исходящие HTTP-вызовы приложения выполняются через **Spring Cloud OpenFeign**, кроме интеграции GigaChat: там сохраняется **`ai-forever/spring-ai-gigachat`**, включая авторизацию, которую обслуживает библиотека. Собственный Feign-клиент к GigaChat не вводится. Stub обязателен и для этой интеграции.

## Конфигурация

Пример автономного запуска прототипа; реальные адреса задаются окружением при отключении соответствующих заглушек:

```yaml
integrations:
  invest-corr:
    stub: "enabled"
    url: "${INVEST_CORR_URL:}"
  gigachat:
    stub: "enabled"
    url: "${GIGACHAT_URL:}"
```

Для испытания на настоящей Ultra: `integrations.gigachat.stub: "disabled"`, адрес выбранного контура и требуемые параметры авторизации. Invest corr при этом может оставаться `enabled`. Для HTTP-контрактного теста corr используется `stub: "disabled"`, а `url` тестовая конфигурация направляет на WireMock/локальный HTTP-стенд. Это проверяет настоящий Feign-путь, но не подтверждает совместимость с ещё не предоставленным API банка.

| Параметр/ситуация | Правило |
|---|---|
| `stub=enabled` | Активен только stub. Реальный клиент, его фоновые задачи, OAuth и соединения не создаются/не запускаются |
| `stub=disabled` | Активен только реальный клиент: Feign либо GigaChat-библиотека |
| `stub` отсутствует либо содержит другое значение | Ошибка конфигурации при запуске. Во включённых интеграциях режим задаётся явно |
| `url` при `disabled` | Обязательный абсолютный HTTP(S) URL; параметры авторизации и TLS проверяются отдельно |
| `url` при `enabled` | Может быть пустым; не используется, его наличие не разрешает сетевой вызов |
| Изменение режима | Применяется при перезапуске приложения; горячее переключение в активном ходе не предусматривается |
| Ошибка реального сервиса | Типизированная ошибка реального вызова. Автоматического переключения на stub нет |

`enabled`/`disabled` — строковые значения, не boolean. Выбор проверяется типизированной конфигурацией; в Spring-контексте должна присутствовать ровно одна реализация каждого клиентского контракта. Недостаточно условно выбирать реализацию при каждом вызове, оставив оба клиента инициализированными. Условия регистрации должны также отключать ненужную автоконфигурацию/создание реального GigaChat-клиента в stub-режиме. Это проверяется запуском без credentials и отсутствием сетевых обращений.

`integrations.gigachat.url` — собственное свойство приложения, которое конфигурационный адаптер передаёт реальному клиенту выбранной версии библиотеки. Оно не считается автоматически распознаваемым свойством starter. Endpoint авторизации, credentials и truststore при необходимости задаются отдельно; секреты не помещаются в URL и Git. Фактическое использование настроенного адреса проверяется контрактным тестом.

## Границы кода

| Интеграция | Общий контракт клиента | Stub | Реальная реализация |
|---|---|---|---|
| Invest corr | `InvestCorrClient` | `StubInvestCorrClient` | `FeignInvestCorrClient`, делегирующий транспортному `InvestCorrFeignApi` |
| GigaChat | `GigaChatClient` | `StubGigaChatClient` | `SpringAiGigaChatClient`, использующий ChatModel выбранной библиотеки |

Названия фиксируют проектную форму, а не наличие готовых классов. Существующий `InvestCorrAdapter` и `SpringAiGigaChatAdapter` сохраняют преобразование DTO и реализацию доменных портов; конфигурация подставляет им выбранный клиент. Клиентский stub GigaChat возвращает данные извлечения той же структуры, включая невалидные ответы для негативных тестов. Он не формирует события FSM и не заменяет Java-политику. Результаты stub не считаются оценкой качества Ultra.

Пакеты каждой интеграции сохраняются: `client`, `dto`, `exception`, `mapper`, `service`, `utils`, `config`. Конфигурация выбирает реализацию в `agent-api-out`, главные параметры собирает `agent-main`. Прикладные порты и retry-оркестрация находятся в `agent-service`; внешние DTO изолированы и преобразуются MapStruct. Новые зависимости `agent-service → agent-api-out` или доступ исходящего клиента к `agent-db` не вводятся.

Внешние DTO/интерфейсы генерируются OpenAPI Maven-плагином при наличии спецификации. Для транспорта используется Feign: допускается генерация совместимого Spring Cloud Feign API либо генерация DTO с отдельно описанным Feign-интерфейсом. Клиент RestTemplate/WebClient, случайно выбранный настройкой генератора, не удовлетворяет ADR. Промежуточная спецификация Invest corr явно помечается как контракт прототипа.

Для включения Feign используется `spring-cloud-starter-openfeign`; сканирование ограничивается клиентами конкретной интеграции. Общий URL передаётся из `integrations.<integration>.url`. Самостоятельные retries Feign отключаются через `Retryer.NEVER_RETRY`; конечная политика повторов с одним ключом и payload остаётся в оркестраторе. Spring Cloud OpenFeign поддерживает эти механизмы. [Документация OpenFeign 4.3](https://docs.spring.io/spring-cloud-openfeign/reference/4.3/spring-cloud-openfeign.html).

Deadline ограничивает всю цепочку, а не только чтение HTTP-ответа. Ограничения транспорта применяются с учётом оставшегося времени; сумма отдельных connect/read timeout не объявляется общим пределом. Нельзя получить скрытые повторы одновременно в Feign, HTTP-транспорте и сервисном слое.

Для принятого Boot 3.5.x исходная совместимая линия Spring Cloud — 2025.0.x; точный BOM/patch фиксируется и проверяется на P1.01. На дату проверки официальная матрица отмечает эту линию как завершившую поддержку: это ограничение выбранного прототипного стека, а не основание автоматически менять согласованные Boot/SSM. [Матрица совместимости и поддержки Spring Cloud](https://spring.io/projects/spring-cloud/).

## Проверки принятого решения

1. Для каждой зарегистрированной out-интеграции тестируются оба режима и отсутствие одновременно активных реализаций.
2. В `enabled` сценарий работает без credentials и обращений к внешнему адресу, в том числе к OAuth GigaChat.
3. В `disabled` используется настроенный URL; для corr это доказывается HTTP-тестом Feign, для GigaChat — тестом адаптера библиотеки.
4. Отсутствующий режим, неизвестное значение и пустой/невалидный URL в реальном режиме приводят к понятной ошибке старта.
5. Stub реализует успех, отказ, ошибку/тайм-аут и нужные сценарию повторы. Выбор fixtures задаётся тестовой конфигурацией, а не пользовательским текстом.
6. Нет автоматического fallback на stub, скрытых генераций LLM и повторов отправки с новым ключом.
7. В автономной демонстрации явно указано, что работают заглушки. Проверка настоящей Ultra выполняется отдельным шагом; настоящие SMS stub не отправляет.

ADR задаёт переключение в прототипе через `application.yaml`, без дополнительного независимого флага `mode`. Тестовые управляющие HTTP-endpoints остаются доступны только в локальном/тестовом UI-профиле. Промышленное подключение и политика допуска stub на production-стендах находятся вне текущего объёма прототипа.
