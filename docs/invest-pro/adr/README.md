# Индекс архитектурных решений (ADR)

Перед работой прочитать этот индекс и действующие решения, относящиеся к задаче. Статус «Принят» означает утверждённое решение, а не завершённую реализацию.

| ADR | Решение | Статус |
|---|---|---|
| [ADR-001](0001-outbound-clients-and-stubs.md) | Исходящие клиенты: stub, конфигурация и Feign | Принят |
| [ADR-002](0002-liquibase-xml.md) | Liquibase XML: один master и общий каталог changeset | Принят |
| [ADR-003](0003-h2-persistence-and-runtime.md) | H2 для тестов persistence и запуска приложения | Принят |

ADR-003 заменяет прежнее требование обязательной PostgreSQL для DB-тестов; остальные правила ADR-002 сохраняются.

## Поддержка индекса

- При добавлении ADR создать файл со следующим номером и добавить строку сюда. Перечень и содержание решений в AGENTS.md не дублировать.
- При изменении статуса обновить индекс и сам ADR. Использовать статусы «Предложен», «Принят», «Заменён», «Отменён»; принятие фиксировать только по решению пользователя.
- При замене решения указать ссылки между старым и новым ADR и область замены. Частичная замена не отменяет остальной документ.
- Обновить затронутые планы/документы; противоречие без явного решения пользователя не разрешать по одному лишь номеру ADR.
