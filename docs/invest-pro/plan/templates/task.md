# Task: <P1.01 — название шага>

**Стадия:** design. **Design revision:** 1. **Статус шага:** Design. **Ссылка на дизайн:** [design.md](./design.md).

Это шаблон. При копировании в папку шага заменить примерные строки реальными checkpoints и test IDs. Ни один пример ниже не означает выполненную работу.

## 1. Согласование и запуск

- [ ] Архитектор описал объём, AC и детальный дизайн.
- [ ] Каждому AC сопоставлены проверяемые тесты; вопросы/развилки записаны.
- [ ] Пользователь ответил на вопросы, документы актуализированы без несогласованных решений.
- [ ] Пользователь явно согласовал текущую ревизию design/task; свидетельство записано.
- [ ] По явному согласованию сразу запущен разработчик; отдельная команда implement не требуется.

Если вопросов не было, соответствующий checkpoint пометить `Н/П: вопросов не было`, а не выдумывать ответы. Блок приёмки нельзя закрывать решением самого агента.

## 3. Свидетельства TDD и тестов

| Test ID / набор | Уровень | Команда | RED: время и ожидаемая причина | GREEN: время, результат, отчёт | Статус |
|---|---|---|---|---|---|
| Заполнить | unit / integration / e2e | После определения в design | Ещё не запускался | Ещё не запускался | Не начат |

Записывать фактический запуск, exit code, число тестов/ошибок/пропусков и путь отчёта, если он создан. Ошибка окружения не является доказательством RED по критерию. Пропуск или отсутствие доступа не считается GREEN. Для сквозных тестов указать stub/real режим каждой интеграции; fixture GigaChat не выдавать за настоящую генерацию.

|---|---|---|---|---|

При новой существенной развилке разработчик фиксирует её и останавливает зависимую работу. После решения архитектор уточняет документы и снова останавливается; продолжение implement требует новой команды. Исправления дефектов в согласованном объёме выполняются через регрессионный тест и TDD без подмены AC.

## 5. Передача результата и приёмка

- Изменённые файлы / результаты / ограничения: заполнить.
- Как воспроизвести пользователю: заполнить проверенные команды и ожидаемый результат.
- Обязательные проверки: не выполнены.
- Готовность разработки: не подтверждена.
- Приёмка пользователем, дата/время: не получена.
- Следующее допустимое действие: определить после текущей остановки.

После GREEN всех обязательных проверок закрыть фактические checkpoints, выставить WBS `Implement на проверке`, обновить корневой `history.md` и остановиться. Только приёмка пользователя переводит WBS в `Выполнен`; следующий шаг начинается новой командой и снова со стадии design.
