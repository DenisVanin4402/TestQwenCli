# Профили change: lite и full

`Change profile` определяет объём `change.md`, `design.md`, `tasks.md`. `Spec update mode` определяет способ обновления master spec; `Apply policy: ai-strict` — строгое применение через ИИ. Эти параметры независимы: lite использует те же копии, хеши, ревью и смысловую проверку конфликтов, что full.

## Выбор

Вход `profile=auto|lite|full`, по умолчанию `auto`. В артефактах записывай выбранное `lite` или `full` и краткое основание. В старом change без поля считай профиль `full`, не требуй переписывать документ только ради поля.

Выбирай **lite**, если область понятна, меняются один или несколько конкретных объектов, есть проверяемые критерии и отсутствуют архитектурные решения, миграция данных, breaking API/события, изменения прав доступа или существенные межсервисные последствия. Число файлов само по себе не определяет сложность.

Примеры: новое значение внутреннего справочника; замена `>` на `>=` в известном бизнес-правиле; исправление обязательности поля при сохранении контракта. Добавление значения публичного enum требует проверки потребителей: исчерпывающий switch или строгая десериализация могут сделать изменение breaking и потребовать full.

Выбирай **full** для нового флоу, изменения нескольких контрактов, миграции, неоднозначных правил или существенных рисков. Если при работе lite вырос до такой задачи, объясни причину и перенеси существующие требования/ID/ссылки в full. Не начинай интервью заново и не теряй согласованные данные. Содержательное изменение требований возвращает статус `На согласовании`.

## Lite workflow

1. Прочитай navigation, manifest и затронутые документы. Уточняй только отсутствующие сведения; достаточное исходное описание не требует многоэтапного интервью или отдельного подтверждения уже заданного scope.
2. Выполни точечное исследование затронутых объектов. Structured research и субагенты не обязательны для lite.
3. Создай `change.md` из `templates/change-lite.md`: цель, конкретное «было → стало», ID изменений и ссылки на копии, ограничения/совместимость, критерии и открытые вопросы.
4. Подготовь [копии документов](../../openspec-apply-change/references/document-copies.md). Один ID изменения может ссылаться на несколько документов, один документ — покрывать несколько ID. Контекстные документы без правок не копируются.
5. После согласования `openspec-design` использует `design-lite.md` и `tasks-lite.md`. По явному запросу допускается пропустить `design.md`, если решение очевидно; `tasks.md` для implement остаётся обязательным. Каноническое имя — `tasks.md`, не `task.md`.
6. Реализация, проверки и apply выполняются по обычному workflow.

В lite не нужны 16 пустых разделов, обязательные диаграммы, каталог альтернатив, многоэтапное интервью и псевдокод для простой замены условия. Достаточны точное правило с границами и критерии проверки. Не опускай реальные риски, зависимости или ошибочные сценарии ради краткости.

## Full workflow

Сохрани действующие аналитические разделы полного шаблона. Дополнительно обязателен реестр «ID изменения → одна или несколько копий документов». Проставь ID и ссылки также рядом с конкретными требованиями в разделах. Реестр не заменяет описание цели, требований и критериев.

Для обоих профилей запрещено выдавать сгенерированные примеры за реальные требования. Согласование относится к `change.md` и содержимому связанных копий вместе.
