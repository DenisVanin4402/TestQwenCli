# Пример lite-change: значение внутреннего справочника

Это учебный пример оформления, а не готовый change для apply. В рабочем v3 change текст находится только в content, review генерируется spec_review.py и проверяется по fingerprint. Ссылки сохраняют исходные имена: `.spec-copy/review/<путь-документа>.md`. ИИ применяет проверенный content по ai-strict. Статические иллюстрации ниже не являются входами генератора.

> **Change profile**: lite
>
> **Spec update mode**: document-copies
>
> **Apply policy**: ai-strict
>
> **Статус**: На согласовании

## Цель и границы

Добавить причину отмены `DUPLICATE` во внутренний справочник заказов. Она фиксирует отмену повторного заказа. Публичный API и внешние потребители этот справочник не используют; хранение уже допускает новые строковые значения. Поэтому достаточно lite.

## Изменения и копии документов

| ID | Объект | Было → стало | Копия с отмеченными строками |
|---|---|---|---|
| CH-01 | Причина отмены | `USER_REQUEST`, `EXPIRED` → дополнительно `DUPLICATE` | [Открыть копию справочника](examples/cancellation-reasons-review.md) |
| CH-02 | Условие повтора | Повторный заказ не классифицируется → при совпадении business key отмена с причиной `DUPLICATE` | [Открыть копию правила](examples/duplicate-rule-review.md) |

## Совместимость и ограничения

Причина доступна только для отменённых заказов. Проверить внутренние enum/switch-потребители. Если обнаружится внешний строгий контракт или миграция, пересмотреть выбор lite.

## Критерии приёмки

| ID | Изменение | КОГДА | ТОГДА |
|---|---|---|---|
| AC-01 | CH-01 | Получен внутренний справочник | `DUPLICATE` есть ровно один раз с описанием «Повторный заказ» |
| AC-02 | CH-02 | Business key совпадает с существующим заказом | Новый заказ отменён с причиной `DUPLICATE` |
| AC-03 | CH-02 | Business key уникален | Создание проходит по прежнему сценарию |

## Открытые вопросы

Нет в рамках учебного примера.

В lite `design.md` содержит только затронутые enum/функцию и выбранную правку. В `tasks.md` достаточно конкретных задач реализации и проверки AC-01–AC-03. ИИ проверяет текущий master и смысл связанных правил: при конфликте требуется решение, независимые изменения сохраняются. Совпадение/различие номеров строк не заменяет смысловую проверку.
