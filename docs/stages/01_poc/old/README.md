# Архив документов первого этапа

**Уточнение от 05.10.2026.** Здесь остаются документы прежних вариантов архитектуры. Расхождение согласованного документа с кодом само по себе не является основанием для архивирования: сначала требуется разобрать расхождение и согласовать изменение.

| Документ | Причина переноса |
|---|---|
| [Исходное ревью сложности](architecture_simplicity_review.md) | Проверяет прежний runtime и содержит устаревшее указание, что реализация ещё не разрешена. |
| [Схемы corr, Outbox и УСС](corr_outbox_uss_sequence.md) | Предыдущий вариант обсуждения с квитанциями доставки, обратным бизнес-результатом и сетевыми вызовами вне транзакций; не описывает реализованный STATUS и согласованный void-контракт менеджера. |

В папку этапа возвращены [план рефакторинга](architecture_refactoring_plan.md), [техническая спецификация](technical_specification.md) и [хронология принятых решений](architecture_simplification_decisions.md). План и спецификация обновлены по решениям пользователя: restart_status удалён, в AWAITING_CONFIRM остаются только CONFIRM/CANCEL, остановка временной FSM выполняется в finally до commit/rollback. Хронология сохраняет основания решений с явным разграничением исторических формулировок и текущего состояния.

Действующие [требования](requirements.md), [архитектура](architecture.md), [C4](c4_architecture.md), [заключение о реализации](architecture_review.md), [ревью кода](code_smells_review.md) и [история](history.md) остаются рядом. Нормативные решения — в [ADR](../../../adr/README.md).

Относительные ссылки внутри перенесённых файлов сохранены как были: для ссылок за пределы архива исходной базой была папка `docs/stages/01_poc`. Архив нужен для истории обсуждения, а не для постановки новых задач.
