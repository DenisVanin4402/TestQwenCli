# Архитектура этапа 1: целевой POC

**Редакция:** 04.10.2026. **Статус:** архитектура реализованного упрощения; полная приёмка пройдена. Прежняя архитектура с owner/fencing, внешней transition policy и corr-result заменена этой редакцией.

## 1. Источники

Нормативные решения — [индекс ADR](../../../adr/README.md), бизнес-объём — [требования](requirements.md). [C4](c4_architecture.md) описывает реализованный путь и границы транзакций. Прежние спецификация, план и основания упрощения перенесены в [архив с причинами переноса](README.md).

## 2. Ответственность

| Компонент | Назначение |
|---|---|
| ACL controller/adapter | Транспортная валидация, корреляция и MapStruct; общий вход в use case без выбора перехода. |
| SessionTurnOrchestrator | Координирует вызов инфраструктуры, получает предметный результат после транзакции, выбирает и заполняет шаблон ответа. |
| SessionExecutionService в agent-service | Обеспечивает семафор, одну рабочую транзакцию и один экземпляр restore/create → execute → native save. |
| SSM guards/actions | Единственный выбор перехода и синхронная бизнес-логика. Результат предметный, без текстов и знания канала. |
| WorkflowManager | Прикладной void-порт. Временный адаптер делает один STATUS Feign-вызов, без повторов и callback. |
| Spring Data/native persister | Техническая SessionEntity-семафор с formatId и native ExtendedState; одна БД/транзакция сохранения. |
| Адаптер ответа | Преобразует подготовленное содержание в ACL-поля/коды; controller возвращает HTTP. |

Границы модулей уточнены [ADR-021](../../../adr/0021-direct-spring-statemachine.md) и [task02](../../../tasks/task02/impl_design.md): сервис непосредственно использует SSM, agent-db предоставляет хранилище без обратной зависимости. Отдельные guards/actions реализуют штатные интерфейсы библиотеки и содержат всю прикладную логику. Собственный протокол переходов удалён.

## 3. Исполнение и сохранение

Сначала отдельная короткая транзакция обеспечивает постоянную строку семафора. Затем рабочая транзакция берёт FOR UPDATE NOWAIT, читает native FSM и formatId, восстанавливает/создаёт машину, полностью исполняет событие через synchronous transition action и сохраняет тот же экземпляр. Commit/rollback освобождает блокировку; строка остаётся. Занятая сессия возвращает SESSION_BUSY без очереди.

Все изменения проходят один семафор до чтения FSM. Отсутствующая машина создаётся при корректном первом входе даже после прошлой неуспешной инициализации; повреждённая не заменяется новой. Внутренний запрос читает снимок через FOR SHARE NOWAIT без событий, записи и corr. Подробности — ADR-008–010/016.

Native ExtendedState хранит контекст, подготовку, согласие и последний предметный результат. Отдельная таблица binding не нужна: один formatId проверяется до десериализации. Готовые тексты и templateId не сохраняются. Входная идемпотентность пока обозначена маркером, без библиотеки runtime-дедупликации.

## 4. Внешняя операция и ответ

Подтверждение вызывает WorkflowManager один раз непосредственно из Action. Только STATUS → submitStatus. OperationContext содержит operationId, epkId, digitalUserId, paymentId и необязательные changes; STATUS не передаёт changes. Транспортные connect/read timeout остаются по 2000 мс, автоматических повторов нет.

Любая ошибка Action достигает транзакционной границы и откатывает локальные изменения. Успешное выполнение и commit завершают FSM в COMPLETED. Затем оркестратор готовит содержание по снимку результата, адаптер — HTTP/ACL. Ошибка шаблона после commit не повторяет операцию.

Временный corr вызывается до commit и ответа GA. Риск внешнего эффекта при локальном сбое принят явно; rollback не является компенсацией corr. Полноценный Outbox/УСС и порядок «ответ GA перед внешним действием» отложены, обратного бизнес-результата в агент не будет.

## 5. Удаление и приёмка

Физически удалить старую внешнюю transition policy, binding-метаданные, command journal/replay, внутренние ключи, владельцев/fencing/node lock, CorrSubmissionService, попытки и события corr-result, retry-конфигурацию и ненужные тесты/модели. Не оставлять альтернативный путь в выключенных beans или deprecated-классах. История действий отложена.

Приёмка по ADR-017 подтверждает реальный сценарий, rollback native/прикладных данных, семафор, PostgreSQL, HTTP и JAR. Старая успешная приёмка не доказывает новую архитектуру. C4 фактической реализации обновляется после рефакторинга по последнему шагу плана.
