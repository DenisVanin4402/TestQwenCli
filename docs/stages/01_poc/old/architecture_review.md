# Проверка реализации первого этапа после рефакторинга

**Редакция:** 05.10.2026. **Статус:** реализация и исправления ревью выполнены; последний полный прогон — 81 проверка без ошибок и пропусков, включая отдельный отказ commit PostgreSQL. Границы проверки приведены ниже. Это заключение заменяет описание прежнего owner/corr-retry runtime. История прежней реализации доступна в Git.

Проверены действующие ADR, требования, спецификация, код восьми модулей и фактические границы исполнения. Отдельный сабагент выполнил [статическое ревью кода](code_smells_review.md); после одобрения пользователя основной агент исправил все R1–R8 и S1–S4. Новая проверка не возвращает снятые механизмы.

## Реализованный путь

ACL adapter/mapper возвращает целый внутренний вход. SessionTurnOrchestrator обеспечивает строку семафора и вызывает транзакционный FsmEngine. Под NOWAIT выполняются одно восстановление, выбор перехода SSM, синхронный Action и native save. При подтверждении Action вызывает один void WorkflowManager по снимку подготовки. Внешний corr вызывается до локального commit; ответ формируется после него.

SessionResponseRenderer использует локальные проверяемые шаблоны для POST и GET; SessionResponseMapper создаёт проекции по именам полей. ResultCode типизирует причины отказов. Известная завершённость проходит через контролируемую ошибку независимо от полной проекции и без повторного чтения FSM. Ни тексты, ни wire DTO не сохраняются в ExtendedState.

MapStruct копирует предметные снимки, а единичные DTO создаются именованными builder-полями. ContextBinding проверяет исходные данные; Guards/Actions — допустимость перехода; NativeMachineStore — формат и целостность сохранённой машины. Локальный ExecutionContext принадлежит одному вызову, не создаёт нового протокола владения.

Прежние facade/policy, binding, журналы команд и corr, owner/fencing, retry/wiring и их модели удалены физически. Liquibase 0001/0002 сохранены; 0003 сводит прикладное хранение к постоянному семафору. Старые checkpoint не конвертируются. Нет SSM-типов в production service/model/API; нет generated wire DTO в ядре.

## Приёмка

| Область | Проверки реального поведения |
|---|---|
| ACL и helper | Адресация, UUID/корреляция, частичные metadata, null/дубликаты/неверные типы, итоговая проекция и ошибки helper 400/500. |
| Сценарий | Подготовка, отказ на повторный выбор в AWAITING_CONFIRM, отмена, новый выбор после отказа, отдельное согласие; отказ на удалённый restart_status без изменения FSM/corr; запрет всех операций после COMPLETED и финальный отказ при подмене контекста. |
| Corr | Реальный generated Feign, payload/ключ, явный отказ, HTTP-ошибка, неполный/неверный JSON, разрыв ответа и отдельный read timeout; один запрос без retry. |
| Транзакция | Action и native checkpoint в общей транзакции; rollback предметной записи/согласия; неуспешное первое сохранение оставляет только семафор. Внешний эффект после rollback не отрицается. |
| PostgreSQL | Параллельная регистрация семафора, NOWAIT для POST/GET, независимость сессий, большой native LOB, повреждённый binary/подготовка и несовместимый formatId. |
| Ответ | Сводка берётся из подготовки; renderer не изменяет снимок; неверные шаблоны отклоняются до запросов. Сбой renderer после commit не отменяет COMPLETED и не вызывает corr повторно. |
| Запуск | Профили H2/PostgreSQL, Liquibase, собранный JAR, остановка/повторный запуск и восстановление подготовки перед подтверждением. |

Полный профиль — `mvn clean verify -Pintegration-tests` с отдельной PostgreSQL через `POC_TEST_POSTGRES_*`. E2E использует настоящие Spring HTTP, PostgreSQL, SSM и generated Feign; внешний corr заменяет управляемый HTTP-стенд. Отчёты Maven остаются в `target`.

До финального прогона R1 и R7 воспроизведены падающими регрессиями. При проверке исправлены синтаксис описания OpenAPI и слишком короткий общий GET-timeout тестового клиента; проверка NOWAIT имеет отдельный ограниченный бюджет. Финальный `mvn clean verify -Pintegration-tests` завершился с exit code 0: **79 проверок, 0 failures, 0 errors, 0 skipped**. Из них 40 Surefire и 39 Failsafe: 28 PocEndToEndIT, 1 PocCorrTimeoutIT, 9 PostgresSessionPersistenceIT, 1 PocJarSmokeIT. Spotless и `git diff --check` пройдены. Отдельная тестовая PostgreSQL остановлена после приёмки.

После отдельного решения пользователя удалён restart_status из API-профиля, mapping, enums, графа и доступных действий. HTTP-регрессия сначала воспроизвела прежний ответ 200 вместо требуемого 400; после удаления команды полная чистая приёмка прошла: **80 проверок, 0 failures, 0 errors, 0 skipped** (41 Surefire и прежние 39 Failsafe). E2E проверяет сохранность предложения и отсутствие corr при удалённой команде, затем отказ, новый выбор и отдельное подтверждение. Последующим решением пользователя из AWAITING_CONFIRM также удалён SELECT; допустимы только CONFIRM и CANCEL.

05.10.2026 добавлен `PocEndToEndIT.commitFailureAfterCorrPreservesLastCommit`: отложенный внешний ключ PostgreSQL нарушается в рабочей транзакции после настоящего persist и проверяется БД при commit. Подтверждены HTTP 500/failure, final_message=false, полное сохранение предыдущей проекции, откат тестовой записи и единственный вызов/эффект corr. В отчёте ошибка проходит через PgConnection.commit и JpaTransactionManager.doCommit. Это проверка известного отказа фиксации, не потери соединения с неизвестным исходом.

`mvn verify -Pintegration-tests` завершился с exit code 0: **81 проверка, 0 failures, 0 errors, 0 skipped** — 41 Surefire и 40 Failsafe (29 PocEndToEndIT, 1 PocCorrTimeoutIT, 9 PostgresSessionPersistenceIT, 1 PocJarSmokeIT). Production-код не менялся. Согласованный порядок `Action → persist → finally: stop → commit → ответ` отражён в ADR, плане и спецификации; перенос остановки после commit не требуется.

## Принятые ограничения

Реальный банковский corr и поверхность GA не подключены; временный HTTP-контракт проверяется локальным стендом. Входная библиотека идемпотентности не подключена, `@Idempotent` остаётся маркером. Внешний эффект до локального rollback необратим; exactly-once и автоматическое восстановление доставки не обещаются. RECALL/DETAILS, LLM/RAG и полноценный Outbox/УСС отложены по ADR.

Дальнейшая работа расширяет операции и каналы по согласованным контрактам. Нет необходимости заранее возвращать старые журналы, retry, владение процессом или универсальную платформу шаблонов.
