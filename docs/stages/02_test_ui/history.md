# История этапа 2

## 05.10.2026 — исправление ACL и переход к чату

По уточнению пользователя экран заменён лентой сообщений с полем ввода и кнопкой «Отправить». Действия задаёт агент: `suggestions` для саджестов, `propose` и `state[].type=CONFIRMATION` для сводки с подтверждением/отказом. Основной ACL и зеркало используют общий mapper. Свободный текст пока вызывает локальное пояснение. Удалены GET сессии, его модели и адаптер; из вспомогательных API осталась загрузка fixtures. GET-восстановление предыдущей итерации ниже больше не действует. Решение: [ADR-020](../../adr/0020-acl-chat-actions.md).

TDD: HTTP-регрессия сначала получила `inform` вместо `propose`, клиентские проверки — отсутствие нового интерфейса действий. Итоговые Surefire-отчёты содержат 43 успешные проверки без пропусков. После clean и исправления HTTP-проверки прошёл `mvn -pl agent-main -am verify -Pintegration-tests -Dtest=PocHttpIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false`: 5 HTTP-проверок и все 40 Failsafe-проверок PostgreSQL, тайм-аута и перезапуска JAR. Остальные unit-проверки прошли при предшествующем прогоне и повторно не запускались. Node: 6 проверок успешно; синтаксис app.js и diff проверены.

Собранный JAR запущен на http://127.0.0.1:18082/test-ui/ с H2 в памяти и stub corr. Сам TestSession из Node прошёл саджест → отказ → саджест → подтверждение → завершение: четыре POST только в зеркало, удалённый GET вернул 404, четыре ресурса UI — 200. Это проверка доставки клиента, не визуальная приёмка. Инструмент браузера не обнаружил доступных браузеров; внешний вид и мобильная раскладка в браузере не проверены.

## 05.10.2026 — UI.1–UI.3: экран и локальное зеркало ACL

Поручение: начать реализацию второго этапа, выделить UI в отдельный модуль и направлять ходы контроллеру-зеркалу в `agent-ui-back`. Разработка и review выполнены одним оркестратором поверх текущего рабочего дерева POC.

Реализованы `agent-ui`, `/test-ui/`, `LocalAclController`, сведения о подключении и начальных действиях в каталоге. Экран показывает платёж, сводку, согласие/отказ, итог и локальную историю. Добавлены GET-восстановление, защита от повторного клика/позднего ответа и отображение неопределённости после сетевого сбоя. Схема и границы — в [спецификации](technical_specification.md) и [ADR-019](../../adr/0019-test-ui-acl-mirror.md).

TDD: новый HTTP-тест первоначально получил 404 вместо экрана; клиентские тесты первоначально не находили реализацию. Дополнительные регрессии выявили несовпадение `STATUS`/`SELECT_STATUS` и непонятное сообщение занятого GET; оба дефекта исправлены.

Проверки: `mvn verify` прошёл, включая настоящий HTTP/H2 и перезапуск JAR. Клиентские Node-тесты: 7 успешно. После финального исправления начальной команды прошёл `mvn -pl agent-main -am verify -Dtest=LocalHelperBoundaryTest,PocHttpIntegrationTest -Dsurefire.failIfNoSpecifiedTests=false`: helper, HTTP-контракт, форматирование, упаковка и перезапуск JAR.

Дополнительно сам `TestSession` вызван из Node против собранного JAR с H2 и stub corr: выбор → отказ → повторный выбор → восстановление новым клиентом через GET → подтверждение → terminal. Ровно четыре POST, все в `/local-api/api/v1/ai/agents/invest-pro`; четыре ресурса UI вернули HTTP 200. Это проверка клиент-серверного пути, не визуальная проверка браузера. Демонстрационный запуск использовал порт 18082 и отдельную H2 в памяти.

Ограничение: инструмент браузера вернул пустой список доступных браузеров; ручной и визуальный проход, в том числе мобильная раскладка и DOM/XSS в браузере, остаётся непроверенным. Автоматическая часть не объявляется полной UI-приёмкой. PostgreSQL не перепроверялся: схема, транзакции и FSM в этом этапе не менялись. UI.4 относится к MVP.
