## Ответственность

Agent-ui содержит HTML/CSS/ES-модули и Node-тесты без зависимостей. TestSession управляет доставкой, корреляцией и локальной историей; app.js безопасно выводит сообщения и кнопки. Серверный LocalHelperController загружает только fixture; его схема ссылается на общее определение AclSuggestion.

Путь хода: браузер → LocalAclController → AclInputAdapter/AclMapper → SessionTurnOrchestrator → семафор/транзакция → SSM → WorkflowManager → native save/commit → renderer → ACL-ответ. Основной ACL-контроллер использует тот же путь. Первоначальный UI не менял FSM; согласованная архитектура [task01](../../tasks/task01/arch_design.md) добавляет программные схемы операций и последовательные guards внутри этого пути, сохраняя транзакционные гарантии. [Дизайн](../../tasks/task01/impl_design.md) и [задачи](../../tasks/task01/tasks.md) ожидают отдельного согласования, код ещё не изменён.

## API и представление

| Маршрут | Назначение |
|---|---|
| /test-ui/ | Ресурсы отдельного agent-ui, только в poc-local. |
| GET /local-api/v1/fixtures | Синтетический платёж, metadata, agentCode, integrationMode, suggestions. |
| POST /local-api/api/v1/ai/agents/{agent_code} | Зеркало общего ACL-контракта. |

GET сессии и его модели удалены. После загрузки fixture UI выполняет только ACL POST по клику. Suggestions создают кнопки действий. Propose создаёт подтверждение/отказ; CONFIRMATION передаёт подтверждаемые реквизиты. После отказа inform содержит status suggestion, после успеха final_message=true и пустые suggestions/state.

В целевом профиле task01 STATUS возвращает paymentNumber и preparationNo; UI возвращает полученный state без собственной схемы и проверок. Состав предложения и проверка согласия используют одну серверную регистрацию операции и сохранённые значения подготовки. Саджесты fixture и последующих ответов получают данные из одного каталога. Подробные изменения классов, формата хранения и тестов ведутся в документах task01.

Исходный YAML и описание 1.5 разрешают propose. В неполной таблице ответов 1.6 он не перечислен; выбранный локальный профиль явно закреплён ADR-020. Готовый текст в content.result является локальной сводкой, не регистрацией шаблона GA.

## Клиент

Conversation_id равен UUID локального диалога. Каждый клик получает отдельный Request-Id/reply_with. Ответ проверяется по conversation_id/in_reply_to; замена объекта диалога отсекает поздние ответы. Старые кнопки удаляются из DOM и не принимаются TestSession. Повторный клик во время ожидания блокируется.

Свободный текст не отправляется; кнопка «Отправить» выводит локальное пояснение. Enter отправляет форму, Shift+Enter переносит строку. После сетевого сбоя автоматического повтора нет. Ошибки HTTP читаются как ACL failure. Хранилище браузера и восстановление отсутствуют: перезагрузка начинает новый диалог без POST.
