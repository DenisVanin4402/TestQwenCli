Предшествующие smoke task01/02/04 автоматически не закрываются. ArchUnit, тесты ради числа, копии Maven-логов/XML в docs, новые таблицы, события SSM и поисковая инфраструктура в план не входят. Обычные детали реализации решаются самостоятельно; изменение границ или контракта возвращается на согласование.

Проверки разработки: новый JSON-контракт и UI дали ожидаемый RED; после реализации GREEN. Дополнительный RED выявил принятие строкового числового маршрута `"0"` через enum coercion; парсер переведён на строгий `MessageRoute.valueOf`. Проверки пройдены последовательными прогонами с исправлением устаревших fixtures. Упаковка исходного JAR заблокирована работающим прежним приложением; сборка и JAR-smoke выполнены в target/task05-build из копии pom/src. Независимая валидация пройдена: [validation.md](validation.md). По последнему указанию пользователя сценарий «Продолжить предыдущую операцию — Да / Нет» вынесен в отдельную будущую доработку и не блокирует task05. Здесь сохраняется согласованное поведение: информационный ответ оставляет прежние кнопки и подготовку; UI отображает их под последним сообщением.
