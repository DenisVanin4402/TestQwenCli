Для разработки запускать узкие затронутые тесты до GREEN; после интеграции один итоговый `mvn -B verify` и `node --test agent-ui/src/test/js/session.test.mjs`. PostgreSQL/JAR можно включить в этот итоговый прогон через существующий профиль `integration-tests` с выбранными IT, например `mvn -B verify -Pintegration-tests '-Dit.test=PostgresSessionPersistenceIT,PocJarSmokeIT' '-Dfailsafe.failIfNoSpecifiedTests=false'`; при таком прогоне повторный обычный verify без новых причин не нужен. PostgreSQL настраивается `POC_TEST_POSTGRES_URL/USER/PASSWORD` на отдельную тестовую БД; недоступность фиксируется как незакрытая проверка, не как успешный пропуск.

Тесты добавляются к существующим наборам без дублирования всех сочетаний на каждом уровне. Существующий baseline совместимости native-снимка должен пройти после добавления метаданных категории enum, без смены formatId. Контракт расширения проверяется review: у нового состояния обязательна категория, у нового промежуточного шага — его представление/данные и отмена; общая навигация не меняется. AWAITING_DETAILS, синхронные проверки и другие будущие шаги сейчас не реализуются. Промпты и предметное качество GigaChat не меняются, платный повтор eval в план не входит. ArchUnit, fixtures Good/Bad, новые механизмы хранения/события и копии логов/XML в docs не вводятся.
