## Проблема и границы

При подтверждении STATUS нужны четыре структурированных поля: **Номер платежа, Организация, Дата платежа, Получатель**. Карточка показывается при первой подготовке и возврате по «Да», в том числе по сохранённой до перезапуска подготовке.

Текст «Сейчас это действие недоступно. Сначала подготовьте запрос и отдельно подтвердите его.» заменяется на «Сейчас это действие недоступно. Есть незавершённая операция.». Вопрос продолжения и кнопки task06 сохраняются. Дополнительно 07.10.2026 пользователь согласовал текст технической ошибки разбора: «Не удалось обработать сообщение. Попробуйте позже.», без изменения навигации для HTTP 500.

Пользователь также поручил заменить перечисления того, чего помощник не знает/не делает, полезной справкой: комиссии, сроки, дни и часы работы, валюты. По последнему уточнению текст оформляется от имени **Банка**, профессионально и понятно обычным пользователям, без оговорок об учебном или вымышленном характере условий. **Комиссия за запрос по рублёвому платежу — 50 рублей.** На «Что делает агент?» и «Что ты можешь?» ответ должен явно перечислять зарегистрированные операции и темы доступной справки. Содержание — в [knowledge.md](knowledge.md).

Изменения относятся к представлению и справке. Тарифы и график — содержание базы знаний; расчёт/списание комиссии, проверка валют и банковский календарь в исполнение операций не добавляются. Полный MVP с RECALL/DETAILS не входит в задачу.

## Исходная реализация до task07

- [SessionResponseRenderer](../../../agent-service/src/main/java/ru/sberbank/pprb/agent/service/turn/SessionResponseRenderer.java) формирует `status.proposal` по схеме согласия: сейчас только номер платежа. [PreparationDTO](../../../agent-model/src/main/java/ru/sberbank/pprb/agent/model/dto/payment/PreparationDTO.java) уже хранит полный контекст; миграция сохранённых подготовок не требуется.
- `INVALID_COMMAND.message` в [каталоге](../../../agent-service/src/main/resources/session-responses.properties) содержит заменяемую фразу. Отдельный `error.INVALID_COMMAND` обслуживает guards, включая отсутствие подготовки; его другая формулировка не относится к запрошенной замене.
- [ACL](../../../agent-api-in/src/main/resources/openapi/acl-poc.yaml) передаёт текст в `content.result`, параметры согласия — в `state[]`. Основной вход и зеркало используют общий mapper. [UI](../../../agent-ui/src/main/resources/test-ui/app.js) выводит строки через `textContent`.
- [Знания](../../../agent-api-out/src/main/resources/knowledge/status-reference.md) и [промпты](../../../agent-api-out/src/main/resources/config/gigachat-prompts.yaml) прямо предписывают рассказывать об отсутствии тарифов, сроков и возможностей. Недостаточно заменить только статьи.
- Классификатор уже получает `OperationCatalog.registeredOperations()`. Справочный provider получает только вопрос и статический ресурс: ему нужно передать каталог, чтобы ответ о возможностях соответствовал регистрации.

## Варианты и выбор

| Вариант | Изменение | Решение |
|---|---|---|
| A — многострочный текст | Четыре строки в существующем `content.result`, без расширения API/UI. | Первоначальная рекомендация; пользователь выбрал B. |
| **B — карточка** | Отдельные поля отображения, жирные подписи, адаптивная раскладка; полный текст для клиентов без карточки. | **Выбран пользователем 07.10.2026.** |

В рамках дополнения о справке рассмотрены два способа: существующий REFERENCE с актуальным каталогом в источниках или новый маршрут с отдельным шаблонным ответом о возможностях. Для реализации согласован первый: он уже поддерживает сочетание вопросов о возможностях, комиссиях и сроках в одном сообщении, сохраняет текущие лимиты вызовов и не требует нового маршрута/исхода FSM. Статический перечень доступных операций в статье не подходит: он может разойтись с регистрацией.

## Принятые требования и детали

**Принято пользователем:** B; четыре поля в указанном порядке; замена фразы; положительное содержание знаний; банковский стиль без оговорок о характере условий; наименование «Банк»; комиссия по RUB 50 рублей; ответ об операциях и справочных темах.

**Согласовано 07.10.2026 в impl_design/tasks:** `content.confirmation_view`, построение текстового представления из той же карточки, дополнение справочного источника каталогом операций, остальные тарифы и расписание из knowledge.md. Пользователь поручил начать реализацию.

Номер берётся из `confirmationSnapshot`, организация/дата/получатель — из `preparation.context`. Дата форматируется настройкой `poc.responses.payment-date-format`. Параметры согласия остаются `paymentNumber` и `preparationNo`.

Пример карточки:

| Запрос статуса платежа | |
|---|---|
| **Номер платежа** | 00042 |
| **Организация** | ООО «Пример» |
| **Дата платежа** | 03.10.2026 |
| **Получатель** | ООО «Получатель» |

Вопрос под реквизитами: «Отправить запрос статуса этого платежа?». Далее — серверные «Подтвердить»/«Отклонить».

## Критерии приёмки

1. Карточка содержит заголовок, четыре поля в заданном порядке и вопрос; длинные значения переносятся, узкий экран сохраняет читаемость. Значения выводятся как текст.
2. Реквизиты принадлежат сохранённой подготовке; номер сохраняет ведущие нули. Первое подтверждение и resume дают одинаковые реквизиты, включая совместимые старые снимки. Повторной подготовки/WorkflowManager при чтении нет.
3. Основной ACL и зеркало передают одинаковую карточку и полное текстовое представление. UI показывает одно представление; при отсутствии/дефекте карточки — текст.
4. Согласие остаётся отдельным сообщением с двумя прежними параметрами; кнопки приходят явно с backend. Представление не сохраняется в native-снимке.
5. Новая фраза `INVALID_COMMAND.message` точна; коды, HTTP-статусы, переходы и навигация task06 сохраняются.
6. Знания содержат комиссии, сроки, график, валюты и порядок обращения, изложенные от имени Банка профессиональным и понятным клиенту языком. Комиссия по RUB — 50 рублей во всех статьях, примерах и контрольных ответах. Ответ о возможностях включает операции из регистрации и темы справки, без списка отсутствующих возможностей.
7. Оба вопроса «Что делает агент?»/«Что ты можешь?» — REFERENCE, без подготовки или отправки. В текущей регистрации ответ называет «Запросить статус»; неподключённые операции не выдаются за доступные. Несколько справочных тем обрабатываются вместе.
8. Числа берутся из согласованных знаний. В статьях и ответах нет оговорок об учебных, демонстрационных или вымышленных условиях. Произвольный тариф из вопроса не меняет источник. Реальное отсутствие источника и технический сбой по-прежнему различаются.
9. Минимальные поведенческие проверки, реальный прогон до 10 вопросов, доступная браузерная проверка и отдельный валидатор выполняются по tasks.md. Ограничение недоступного браузера фиксируется, а не считается пройденной приёмкой.
