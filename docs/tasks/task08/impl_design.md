## 1. Справочный provider и источники

В `ReferenceAnswerProvider` вернуть `answer(String question)`. Удалить аргумент каталога из ветки REFERENCE в `SessionTurnOrchestrator`, выключенной реализации в `PocConfiguration`, mocks и evaluation. Классификатор продолжает получать `operations.registeredOperations()`.

В `GigaChatReferenceAnswerProvider`:

- Удалить построение KB-00 и зависимости от OperationSpecDTO/операций. Прочитать настроенный Resource в UTF-8, передать его полное содержимое в `{{knowledge}}` без добавлений и изменения текста. Подстановки выполнять так, чтобы содержимое ресурса и вопроса не интерпретировалось как шаблон.
- Удалить распознавание заголовков `## KB-N.`, запрет KB-00 и требование наличия определённой структуры. Сохранить ошибку конфигурации для нечитаемого/пустого ресурса. Непустой ресурс без меток можно загрузить, но найденный ответ без допустимого источника выдать нельзя.
- Распознавать в ресурсе только самостоятельные идентификаторы формата `KB-[0-9]+`, независимо от Markdown/обычного текста/JSON. Использовать полные метки, без совпадения KB-01 с KB-010. Повторные упоминания одной метки объединяются, а не считаются ошибкой заголовков. Статическая KB-00 — обычная допустимая метка; фиксированного списка номеров нет.
- Сохранить `ReferenceAnswerDTO(found, answer, sourceIds)` и JSON Schema из DTO. Найденный ответ требует непустого answer; sourceIds — список уникальных строк правильного формата, присутствующих в ресурсе. Модель получает инструкцию ссылаться только на разделы, которыми подтверждается ответ. Это проверка контракта и наличия ссылки, не программная проверка смысла ответа.

| Результат модели | Обработка |
|---|---|
| found=true, непустой answer, непустые корректные sourceIds | REFERENCE_ANSWER |
| found=true, непустой answer, sourceIds=[] | Прежнее преобразование в found=false/answer=null/sourceIds=[]; текст отбрасывается |
| found=false, answer=null, sourceIds=[] | REFERENCE_NOT_FOUND |
| Неизвестная/неправильная/повторная метка, нарушенная форма или противоречивые поля | REFERENCE_FAILED, HTTP 500 |
| Сбой модели/транспорта | REFERENCE_FAILED, HTTP 500, без повторной генерации |

Строгая проверка типов, лишних полей, повторных JSON-ключей и текста после объекта сохраняется. Дополнительной генерации для поиска источника/исправления JSON нет. `ReferenceAnswerDTO` менять не требуется.

## 2. Промпт и знания

В reference-блоке `gigachat-prompts.yaml` убрать указатель конкретных статей KB-00…KB-10, отдельный источник каталога, тарифы и предметные ответы-примеры. Оставить общие инструкции: ответ только по KNOWLEDGE, ссылка на использованные разделы, несколько вопросов/частичное покрытие, отсутствие сведений, банковский стиль, запрет выполнять действия/принимать согласие и требуемый JSON. Формат метки источника — часть контракта, а не указатель тем.

Сохранить явную задачу и блок клиентского вопроса в user-промпте, исправившие не-JSON ответ на «Что ты можешь?». Правило о возможностях сформулировать без номеров статей: назвать описанные в знаниях операции и темы справки. Не приписывать модели текущие кнопки или состояние сессии. По результатам реальных проверок дополнительно явно заданы три именованных JSON-поля, запрет приписывать числам из вопроса неподтверждённое назначение и разделение действий операции/тем справки. Предметные факты в промпт не возвращаются.

В `knowledge/status-reference.md` добавить обычный раздел о поддерживаемой операции «Запросить статус» с её подготовкой и отдельным подтверждением (например, KB-11). Существующие тарифы/график и оформление KB-01…KB-10 допустимо сохранить: они являются содержимым этого ресурса, а не требуемым форматом загрузчика. «Предыдущую операцию» заменить на «незавершённую операцию». Добавление операций сопровождается обновлением знаний вручную; автогенерации или синхронизатора нет.

## 3. Отказ после отмены

В `session-responses.properties` сделать `INVALID_COMMAND.message` нейтральным: «Сейчас это действие недоступно.». Добавить отдельный шаблон для активного шага: «Сейчас это действие недоступно. Есть незавершённая операция.».

В `SessionResponseRenderer.renderOutcome` выбирать активный шаблон только для INVALID_COMMAND и категории INTERMEDIATE сохранённого снимка; новый шаблон проверить при старте. `withNavigation` по-прежнему добавляет вопрос и «Да»/«Нет» только на промежуточном шаге. Guard-ошибка `error.INVALID_COMMAND`, остальные исходы, согласие, карточка, переходы и persistence не меняются.
