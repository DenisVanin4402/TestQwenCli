# Внедрение SDD/OpenSpec в команде НСиР

Этот каталог содержит пакет материалов для вводной встречи и последующей рабочей практики команды НСиР: невыясненные суммы и расследования.

Материалы адаптируют текущий folder-based SDD/OpenSpec framework под реальность команды:

- документация переезжает из Confluence в `docs-hub` и хранится как Markdown/контракты/диаграммы в Git;
- код сервисов остается в отдельных репозиториях;
- один из сценариев работы аналитика сохраняет привычную модель "меняю несколько страниц под одну Jira-задачу", но вместо цветовых выделений в Confluence используется ветка, diff и PR;
- master specification не является одним большим файлом, а представляет собой набор директорий и файлов по сервисам, интеграциям, моделям, справочникам, workflow и фронту;
- команда работает без отдельной роли тестировщика: качество закрывается аналитическим ревью, приемкой аналитиков и автоматизированными тестами.

## Рекомендуемый порядок использования

1. Перед встречей прочитать `meeting-plan.md` и выбрать один реальный или демонстрационный change.
2. На встрече показать не весь фреймворк, а три входа аналитика: `explore`, `propose`, ручные правки docs-hub с `change-from-diff`.
3. После встречи закрепить `team-guide.md` как рабочий процесс команды.
4. Для первых задач использовать `scenarios-and-prompts.md` как набор готовых команд агенту.
5. На пилоте каждую неделю проходить `pilot-checklists.md` и фиксировать, где процесс помогает, а где мешает.

## Три входа в процесс

```text
Режим A: explore
  -> аналитик исследует область
  -> получает карту документов, кода, gaps и вопросов
  -> решает: propose, docs branch или refresh

Режим B: propose
  -> аналитик формулирует изменение в чате
  -> агент читает master spec и проводит интервью
  -> создается change.md

Режим C: change-from-diff
  -> аналитик вручную меняет документы в ветке
  -> агент строит change.md из Git diff
```

## Короткая формула полного процесса

```text
Jira-задача
  -> explore / propose / docs branch
  -> openspec/changes/<change>/change.md
  -> ревью и статус "Согласовано"
  -> design.md + tasks.md
  -> реализация в code repo
  -> тесты и приемка
  -> verify master-spec source
  -> archive change
```

Ключевой сдвиг для НСиР: цветовые выделения в Confluence заменяются на Git diff и `change.md`, но аналитик по-прежнему работает с понятной предметной документацией, а не с техническим single-file шаблоном.
