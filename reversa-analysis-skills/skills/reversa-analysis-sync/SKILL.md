# Актуализация системной аналитики


Прочитай [стандарт](../reversa-analysis/references/standard.md) и [правила актуализации](../reversa-analysis/references/update.md). Вход — существующий пакет, исходная и новая версии материалов либо конкретное решение пользователя.

## Порядок

1. Прочитай текущие scope, catalog.json, evidence.json, traceability.json и доступные решения. Не начинай полную генерацию поверх готовой аналитики.
2. Запусти impact по [командам](../reversa-analysis/references/commands.md). Он показывает изменённые, недоступные и непроверенные источники и связанные документы. Это кандидаты для анализа, не доказательство изменения бизнес-правила.
3. Изучи содержательный diff источников. Установи, какие утверждения изменились, какие лишь переместились, какие нельзя проверить. Учитывай зависимости FR/ALG/WF/AC и общие справочники.
4. Подготовь точечные изменения. Сохраняй ID и предметные формулировки, если смысл прежний. Изменённые согласованные документы помечай требующими нового ревью; прежнее согласование сохраняй в записи изменения с исходной версией, не присваивай его новому тексту автоматически.
5. При конфликте ручной аналитики с новой реализацией сохрани обе стороны: наблюдение и действующее требование. Реализация не отменяет требование сама по себе. Не разрешай неопределённость массовой перегенерацией.
6. После сверки обнови только обработанные источники, их версии/хэши и claims. Общий baseline не повышай, пока не объяснены оставшиеся источники прежней версии.
7. Обнови примеры, AC, навигацию и отчёт проверки. Перечисли затронутое, неизменённое и неподтверждённое.

Команда impact ничего не записывает. Для отчёта используй [проект изменения](../reversa-analysis/assets/templates/change.md). Если источник недоступен, работай с доступной частью и сохрани конкретный пробел; не считай недоступность удалением возможности.
