# Системная аналитика — полный цикл


Создай рабочую спецификацию, по которой читатель без исходного кода может понять поведение, рассчитать примеры и поставить задачу. Этот набор — самостоятельное дополнение к Reversa, а не его штатный модуль.

## Вход и границы

Установи систему, разрешённые источники, их версию и объём запроса. Используй уже заданные пользователем пути и ответы. Для локального проекта прочитай действующие инструкции и доступные материалы Reversa по [карте источников](references/reversa-inputs.md). По умолчанию создавай отдельный каталог аналитики \_reversa_analysis; фактический путь выбирай в разрешённой области. Не меняй исходники, результаты извлечения Reversa или общие инструкции агента ради построения документации.

Прочитай [общий стандарт](references/standard.md). Если источников нет, подготовь честный каркас и перечень необходимых сведений; не объявляй его завершённой аналитикой. Для TO-BE можно использовать пользовательские требования без исходников, сохраняя их происхождение. Если объём уже понятен, начинай работу без повторной анкеты и подтверждений между этапами.

Это этапы работы, а не требование запускать отдельные процессы. Прочитай нужный соседний SKILL.md и выполни его в текущем контексте. Для локального изменения не повторяй весь цикл. Дополнительные агенты необязательны и используются только если это разрешено средой и задачей.

## Организация результата

Удерживай общую модель отдельно от документов capability. Используй [шаблоны](references/template-index.md) и [контракт реестров](references/package-contract.md). Число документов определяет предметная область: группируй маленькие связанные описания, дели слишком крупные. Не привязывай одну capability к одному модулю и не копируй структуру Arch Explorer в другую систему.

Регистрируй источники и утверждения по мере работы. Неизвестность связывай с конкретным вопросом и влияющим сценарием. Прежние решения сохраняй, но не выдавай направление изменения за выполненную реализацию. Для долгой работы записывай в analysis-config.json завершённые этапы, область, версии и следующий шаг; при возобновлении сначала сверь файлы и источники.

Заверши цикл ревью и сборкой Markdown. В результате сообщи входной README, фактическую область, выполненные проверки и оставшиеся вопросы. Для локальных команд используй [помощники](references/commands.md). Генератор каркаса и валидатор не заменяют работу аналитика.
